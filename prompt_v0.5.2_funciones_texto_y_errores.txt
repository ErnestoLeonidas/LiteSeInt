Quiero que implementes la version 0.5.2 de LiteSeInt.

Contexto del proyecto:

- LiteSeInt es un interprete web de pseudocodigo con shell y carga de scripts en `index.html`, estilos en `css/styles.css`, controlador de UI en `js/app.js`, validador/tokenizador en `js/doc_errores.js` y runtime/parser en `js/LiteSeInt.js`.
- La fase `0.5.0` debio dejar mejor organizado el sistema de expresiones.
- La fase `0.5.1` debio agregar operadores nuevos y funciones numericas nativas.
- Esta version `0.5.2` debe cerrar la serie `0.5.x` con funciones nativas de texto y una mejora general de errores, ejemplos y documentacion.
- Respeta la arquitectura y los limites por archivo descritos en `CLAUDE.md`.

Objetivo de esta fase:

Implementar soporte para estas funciones nativas de texto:

- `Longitud(texto)`
- `Mayusculas(texto)`
- `Minusculas(texto)`

Y aprovechar esta version para mejorar:

- mensajes de error relacionados con expresiones y llamadas
- ejemplos precargados
- autocompletado
- documentacion

Importante:

- Esta version debe construir sobre la arquitectura de expresiones ya refactorizada.
- Si detectas que la base de `0.5.1` no esta completa o tiene pequenas inconsistencias que bloquean `0.5.2`, corrige solo lo minimo necesario para soportar esta fase sin reabrir el alcance completo de `0.5.1`.
- No debe invadir el alcance de `v0.6.x`, que segun el roadmap corresponde a validacion en vivo dentro del editor.
- Tampoco debe mezclar arreglos, persistencia local ni funciones de usuario.

Alcance funcional esperado:

1. `Longitud(texto)`

- Debe devolver la longitud de una cadena.
- Debe poder usarse en asignaciones, `Escribir`, condiciones y expresiones mas grandes.

Ejemplos esperados:

```txt
Definir nombre Como Caracter
Definir largo Como Entero

nombre = "LiteSeInt"
largo = Longitud(nombre)
Escribir largo
```

```txt
Si Longitud(nombre) > 0 Entonces
  Escribir "Hay texto"
FinSi
```

2. `Mayusculas(texto)`

- Debe convertir una cadena a mayusculas.
- Debe aceptar variable o literal de texto.

Ejemplo:

```txt
Definir saludo Como Caracter
saludo = Mayusculas("hola mundo")
Escribir saludo
```

3. `Minusculas(texto)`

- Debe convertir una cadena a minusculas.
- Debe aceptar variable o literal de texto.

Ejemplo:

```txt
Definir nombre Como Caracter
nombre = Minusculas("HOLA")
Escribir nombre
```

4. Integracion con expresiones existentes

- Las funciones deben convivir con:
  - variables
  - literales
  - parentesis
  - concatenacion
  - comparaciones
  - operadores logicos cuando corresponda

Ejemplo orientativo:

```txt
Escribir "Largo: ", Longitud(Mayusculas(nombre))
```

Objetivos tecnicos:

1. Runtime consistente

- `js/LiteSeInt.js` debe resolver correctamente las funciones de texto.
- Si ya existe una tabla central de funciones nativas, reutilizala y extendela.
- No agregues logica dispersa si la arquitectura ya permite una integracion limpia.

2. Validacion estatica alineada

- `js/doc_errores.js` debe aceptar la nueva sintaxis de llamadas y no generar falsos positivos.
- Si haces validacion de argumentos, mantenla consistente con el runtime.
- El validador y el motor deben aceptar la misma sintaxis.

3. Mejora de errores

Esta version debe aprovecharse para mejorar mensajes en casos como:

- funcion desconocida
- llamada mal cerrada
- cantidad incorrecta de argumentos
- tipo incorrecto de argumento
- expresion mal formada alrededor de una llamada

Quiero errores claros, concretos y utiles para un entorno educativo.

4. Mejora de ejemplos y documentacion

- Agrega o actualiza ejemplos precargados para mostrar funciones de texto.
- Asegurate de que README y changelog expliquen bien las nuevas capacidades.

No objetivos de `v0.5.2`:

- No implementar validacion en vivo mientras se escribe.
- No agregar `Dimension`, arreglos o indices.
- No agregar `Funcion`, `SubProceso` ni funciones definidas por el usuario.
- No introducir persistencia local ni flujo de archivos.
- No seguir expandiendo funciones numericas mas alla de lo ya definido en `0.5.1`, salvo ajustes menores necesarios.

### `CHANGELOG.md`

Decisiones de implementacion que debes tomar con criterio:

1. Dominio de tipos

- Define claramente si `Longitud`, `Mayusculas` y `Minusculas` aceptan solo `Caracter` o si tambien permiten conversion controlada desde otros tipos.
- Si eliges restringirlas, el error debe ser claro.

2. Tipo de retorno

- `Longitud` debe devolver un valor numerico coherente con el lenguaje.
- `Mayusculas` y `Minusculas` deben devolver `Caracter`.

3. Nombres oficiales

- Usa exactamente los nombres:
  - `Longitud`
  - `Mayusculas`
  - `Minusculas`
- Mantén consistencia entre runtime, validacion, autocompletado, ejemplos y documentacion.

Criterios de salida:

- Se pueden usar `Longitud`, `Mayusculas` y `Minusculas` en expresiones reales.
- La validacion estatica y el runtime aceptan la misma sintaxis.
- Los errores de llamadas son mas claros que en versiones anteriores.
- El autocompletado, README, changelog y ejemplos reflejan la nueva capacidad.
- No se rompen los programas validos de `0.5.0` y `0.5.1`.
